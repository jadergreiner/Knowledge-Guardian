# KGD-013 — Authorize KG-002 contract delivery

**Date:** 2026-08-02  
**Type:** Technical and delivery governance  
**Status:** Accepted  
**Decision owner:** Human Tech Lead

## Context

`KG-002 — Repository Document Model` completed shaping and satisfies the operating-model Definition of Ready. The bounded proposal covers versioned data contracts and contract tests only.

## Decision

Approve `KG-002` for contract delivery.

Authorized scope:

- versioned contracts for `RepositorySnapshot`, `Resource`, `Document`, `Classification`, `Relationship`, `EntryPoint` and `Exception`;
- representative valid and invalid fixtures;
- deterministic contract tests;
- contract-version and compatibility documentation;
- validation evidence and known limitations.

## Explicit exclusions

This decision does not authorize:

- filesystem scanning;
- Markdown or YAML parsing;
- repository traversal;
- relationship discovery;
- rule execution;
- finding generation;
- report generation;
- `KG-003` implementation;
- CI/CD blocking or automatic repository modification.

## Rationale

The document model is sufficiently shaped to move from conceptual design into executable contracts while preserving a narrow, independently testable increment. Separating contract delivery from scanner implementation limits architectural coupling and allows model defects to be discovered before parser and traversal decisions become embedded.

## Required delivery evidence

Before `KG-002` can be marked complete, delivery must provide:

1. exact versioned schema files;
2. positive and negative fixtures for each contract boundary;
3. executable validation results;
4. deterministic test execution instructions;
5. compatibility and versioning rules;
6. documentation impact assessment;
7. unresolved limitations and risks;
8. a Tech Lead quality decision.

## Consequences

- `KG-002` moves to delivery planning and bounded contract implementation;
- `KG-003` remains blocked;
- any material change to identity, authority, layer or relationship semantics returns to shaping;
- passing schema tests does not authorize repository scanning.

## Review trigger

Review after all contract schemas and tests are implemented, or earlier if implementation exposes a material model ambiguity.
